# Calendar event editor keyboard access

The native Day, Week, and Month calendars render each booking time with `CalendarViewModel::eventTimeAnchorHtml()`. That helper emits an `a.event_time` with `onclick="event_time_click(this)"` and no `href`, so the individual booking time was not in the normal tab order. The workbench's selected first-booking action does not provide per-event access across these views.

The shared on-screen Twig script now enhances only `#bigCal div.event_appointment a.event_time:not([href])` at document ready. It adds `tabindex="0"` and `role="button"`. Unmodified, non-repeating Enter or Space on the anchor prevents the keydown default and calls the existing `event_time_click(this)` once. Descendant key events are ignored. A namespaced keydown handler is replaced if the ready wiring runs again. The helper still finds the enclosing `div.event_appointment`, and the original `EditEvent`/`oldEvt`/`oldGroupEvt` path keeps its date, event id, category/provider, group session restoration, and dialog sizes. Mouse clicks, event double clicks, other keys, existing `href` links, and other controls retain their existing handlers. Print templates do not include this shared script.

This is an access prerequisite for the existing editor. It does not deliver appointment moving, conflict resolution, or audit behavior, and it adds no route or clinical write rule. The [all-22 feature acceptance register](ACCEPTANCE.md) and its existing clinical gates remain in force. Swedish authority certificate/signature and publication gates also remain separate and unchanged. Ordinary review and approval still apply before delivery.
