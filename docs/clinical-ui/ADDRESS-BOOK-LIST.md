# Address Book list workbench presentation (OPEMR-73)

Status: local, partial presentation slice. The accepted research in [DESIGN-FIDELITY.md](DESIGN-FIDELITY.md) and [RESEARCHED-WORK-AREAS.md](RESEARCHED-WORK-AREAS.md) supplies the light clinical workbench direction; this change does not implement the full researched design or close any of the 22 features in [ACCEPTANCE.md](ACCEPTANCE.md). The preservation and runtime parity gates in [PLAN.md](PLAN.md) still apply.

## Route and real callers

`interface/usergroup/addrbook_list.php` is the existing list, filter, selection, and add/edit route. `AddressBookWidget` in `interface/super/edit_globals.js` opens `?popup=2` in a `modal-lg` dialog 500 pixels high, installs `contactCallBack`, and places the returned user ID in its input. The fax/SMS contact page at `interface/modules/custom_modules/oe-module-faxsms/contact.php` opens the same route with `?popup=2&type=` and `dialogId: 'fax'`, uses `sizeHeight: 'full'`, and handles the selected contact through its own `contactCallBack`. The list's selection path calls `dlgclose('contactCallBack', userid)`; its add and edit paths still open `addrbook_edit.php` at 650 pixels by 75% of available screen height. The direct Administration address-book route and legacy-mode presentation remain relevant paths for acceptance.

## Source-based context and presentation chain

The list calls `Header::setupHeader(['common'])`. `src/Core/Header.php` reads `config/config.yaml`, whose `workbench-popup` asset entry autoloads `interface/clinical-workspace/popup.js` and `popup.css` through that common header path. `popup.js` follows a same-origin parent/opener chain to a workbench host, observes its `workbench-active` mode, and adds `oe-workbench-context` to this page's `<html>` only while that context is active. It removes its owned class when mode changes or the page is hidden. The route's new `oe-address-book-list` body class combines with that HTML class to gate all three local selectors. This is a source and isolated VM chain, not a live render claim.

The additions are one `<style>` element just before `</head>` and one body class. These DOM additions exist in all media and in legacy mode, but their declarations are inside `@media screen` and require `html.oe-workbench-context`; the local colours therefore target only the active workbench screen. The body receives ink `#26383d` and canvas `#f5f2ed`; the real `.body_title` header and `.table` each receive paired ink `#26383d` and paper `#fffefa`. The body and header backgrounds are the two narrow `!important` declarations: the body rule addresses the theme's important `.body_top` background, and the header rule addresses the important `.body_title` background in `interface/themes/colors/utilities/tabs-full.scss`. The table background remains normal. Computed results still need browser inspection. It does not change fonts, the fixed header, the table's 110-pixel offset, controls, row states, geometry, SQL, ACL, CSRF, session handling, escaping, or callbacks. It is a deliberately small screen presentation step. The screen-only rules do not establish print equivalence: the all-media body marker and style element remain in the DOM, and print rendering still needs comparison with the original.

The shared popup stylesheet already colours ordinary popup tables and form controls. The list's table also carries `table-sm`, `table-bordered`, `table-striped`, and `table-hover`; theme CSS may supply important stripe and header backgrounds. The new table ink/paper pair does not prove effective contrast for every cell or state. In default, dark, and solar themes, inspect computed foreground/background and visual contrast for plain and striped rows, the table header, hover and selected/semantic states, labels, inputs, select, checkbox, Add New and Search controls, disabled states, and visible keyboard focus. Preserve semantic colours and state cues. No descendant, control, hover, or focus palette is added here.

## Acceptance still required

Open the real list through both callers and directly, then resize the native dialog through narrow and short viewports. Check fixed header and table overlap, horizontal reachability of every column, scrolling, long or translated labels, zoom, and RTL. Use keyboard-only navigation to reach filters, Type, External Only, Add New, Search, and rows; verify visible focus, search submission, add/edit dialogs, selection callback and return to the caller. Repeat in default, dark, and solar themes, active workbench and legacy mode, and compare screen with print/print preview. These are pending native acceptance checks, not results of the source contract.

The existing text labels use `for` values without matching input `id` attributes, and the NPI field's visible label says “Specialty.” Both are inherited defects left untouched under this exact-additions scope. They need separate accessibility and copy work; this slice does not claim to repair them.
