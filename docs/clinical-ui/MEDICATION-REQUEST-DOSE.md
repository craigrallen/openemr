# OPEMR-204: MedicationRequest dose quantity

`FhirMedicationRequestService::populateDosageInstruction()` previously passed `prescription_drug_size` through `intval()`, truncating a numeric dose such as `1.25` to `1` in `dosageInstruction[0].doseAndRate[0].doseQuantity.value`. It now uses PHP numeric conversion after the existing `!empty` and `is_numeric` guards. Finite fractions remain numeric fractions; integer inputs, including the PHP64 integer string `9007199254740993`, retain integer behavior. Nonfinite or out-of-range numeric values use the prior `intval()` conversion so a nonfinite value is not sent to JSON. The outer dosage guard, zero omission, text, timing, route, units, and `dispenseRequest.quantity` are unchanged. This is a dose value conversion, not a reinterpretation of drug strength.

## Source path and evidence

`PrescriptionService` projects `prescriptions.size AS prescription_drug_size` in its native SQL read. `sql/database.sql` declares `prescriptions.size` as `varchar(25)`, and `Prescription::set_size()` retains numeric punctuation in the string it stores. These sources explain why a fractional numeric string can reach the service, but this work did not execute SQL, a prescription write, a native endpoint, or persistence. In particular, `set_size()` strips exponent notation; the fixture's scientific-notation case exercises the service input, not a demonstrated database round trip.

At the tests-only HEAD `af953f6a`, the controller's original-source RED fixture ran 21 cases: 16 passed and five failed on semantic truncation of `.5`, `1.25`, a fractional float, `-1.25`, and `1.25e1`; there were no setup errors. After the product change, the direct PHP fixture ran 21/21 with zero errors. It loads the complete native service and model/helper source files, invokes `populateDosageInstruction()` on a native `FHIRMedicationRequest`, and checks native JSON serialization. Only the I/O-bearing base declaration is synthetic; the service constructor is bypassed. The fixture also checks integer behavior, guards, metadata, unit, text, timing, route, and the absence of an unexpected dispense request.

`php -l` passed for the product file and PHP fixture; `node --check` passed for the Jest adapter; `git diff --check` passed. Jest was not run locally. The direct fixture does not establish full FHIR parsing, authenticated endpoint behavior, database behavior, security, clinical acceptance, or acceptance of the original 22-feature programme. Ordinary approval and hosted full gates remain pending; this change has not been merged or deployed.
