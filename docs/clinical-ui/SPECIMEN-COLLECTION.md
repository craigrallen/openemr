# OPEMR-214 — FHIR specimen collection codes

Date: 2026-11-05. Supplied tests-only head: `ca020e171e235cc13478fbaa5aef30b2e75ec3aa`. This is supporting existing patient-record interoperability, not acceptance of the researched UI, the original 22-feature register, or Swedish completion.

## Source path and fix

`FhirSpecimenService::searchSpecimens()` projects `ps.collection_method_code`, `ps.collection_method`, `ps.specimen_location_code`, and `ps.specimen_location` from `procedure_specimen`. `createSpecimenRecordFromDatabaseResult()` maps those columns to `method_code`, `method`, `location_code`, and `location`. The existing inner `parseOpenEMRRecord()` branches already build SNOMED CT method and body-site codings when either the relevant code or description is nonempty. The outer collection guard previously checked descriptions and dates but omitted both codes, so a code-only record had no collection. The production change adds `!empty($dataRecord['method_code'])` and `!empty($dataRecord['location_code'])` to that single guard, matching the inner branches. Reversing that exact guard expansion reproduces the baseline product hash, proving no other product source bytes changed.

The existing specimen row template at `interface/forms/procedure_order/templates/procedure_specimen_row.php` has separate method and location code selectors and description inputs. `interface/forms/procedure_order/common.php` fills the description inputs on selector changes. `interface/forms/procedure_order/procedure_order_save_functions.php` reads and persists the two codes and two descriptions independently, converting blank descriptions to null. Thus an identified, nonblank specimen row can retain a code without a description. The fixture also covers absent and empty description keys in synthetic internal rows. This source path supports the code-only parser case; it does not establish a connected caller for `updateSpecimen`.
