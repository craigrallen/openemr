# OPEMR-83: Configure Orders help in the workbench

## Scope and integration

The Configure Orders help route adds a route-specific body class and five screen-only paint rules inside its existing `<head>`. The selectors require both `html.oe-workbench-context` and `body.configure-orders-help-workbench-route`, so the route receives the workbench canvas, paper, and ink colors only when the workbench context is active. The direct child selector limits paper styling to the route's help container. The link selector excludes `.btn`, retaining the instructional buttons and worksheet download button. The two `!important` declarations override existing help-theme paint on headings and return-to-top icons; they do not redefine the orange and red semantic warning icon colors. No layout, geometry, font, focus, control, or interaction rule is added.

The actual caller is `interface/orders/types.php`. When `enable_help == 1`, it renders the help link, sets `helpFile` to `configure_orders_help.php`, and includes `interface/help_modal.php`. That modal assigns the route URL to `#targetiframe` on click. Its ordinary Bootstrap modal has no `.dialogModal` ancestor. In the workbench, the same-origin help iframe can resolve through the content frame to the active shell; the existing popup controller then puts `oe-workbench-context` on the help document's `<html>`, without assigning `oe-workbench-popup`. The controller removes the context when the shell leaves workbench mode or the help page is hidden. With no active shell, the new route styles do not match. This change does not create a caller or alter help eligibility, roles, authentication, or session handling. The `enable_help == 2` hint and `enable_help == 0` absence remain as implemented by the caller; actual access under different roles and sessions is unverified.

The route retains all five sections: single test, panel of tests, custom favorites, multiple orders, and electronic orders. It retains the worksheet link and `download="Configure Orders Worksheet"`, external references, translation calls, instructional sample buttons, show/hide behavior, and orange/red warning icons. The pre-existing `<title>` says “Message Center Help” while the page heading says “Configure Orders Help”; this legacy mismatch remains unchanged.
