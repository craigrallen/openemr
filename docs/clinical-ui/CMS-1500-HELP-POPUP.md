# CMS-1500 help in the workbench

## Route and source boundary

The help document is `Documentation/help_files/cms_1500_help.php`. Its authentic baseline is the 8,803-byte file at `18647270e0c799189d2dc10f801e8de2bff1a360`, preserved byte for byte in `tests/js/fixtures/cms-1500-help-popup-original.php.txt`. The route adds only a body marker and a five-rule, `@media screen` palette block. The marker exists in the DOM in every media mode; the new colors apply only on screen when `html.oe-workbench-context` is present. The route keeps the original 768-pixel responsive CSS, PHP, translations, font and geometry rules, both section anchors, warning icons and text, duplicate external-link `show_hide` IDs, and the NUCC and CMS PDF links with their metadata. Its historical billing and form-date statements remain source content, not current clinical or billing advice.

The selectors pair the canvas with ink on the body, paper with ink on the direct help container, paper with ink on section headings, and transparent backgrounds with ink on ordinary links and redirect icons. The heading background and redirect ink use the two existing-theme cascade overrides marked `!important`. No button, semantic warning color, control, font, or layout rule is added. Changing ancestor backgrounds can change the appearance around the red and orange warning icons; preservation of their classes alone does not establish effective contrast.

## Real caller and context path

`interface/forms/misc_billing_options/new.php` supplies `show_help_icon => true` and `help_file_name => "cms_1500_help.php"` to `OemrUI`, renders `pageHeading()`, and emits `oeBelowContainerDiv()`. The caller reads encounter and patient context, may query or fetch the form, and can change billing session and current patient/encounter state on a GET with `isBilling`. Treat it as an actual application route, not a safe read-only probe; do not execute it for this change.

`src/OeUI/OemrUI.php` registers the heading help listener only when `enable_help !== 0` and the requested help icon is set. The listener's title differs for `enable_help == "1"` and `== "2"`; icon construction and modal emission are distinct gates. `oeBelowContainerDiv()` emits the ordinary Bootstrap `#myModal` when `display_help_icon` is true. Its `#targetiframe` begins with an empty `src` and a help-file `data-src`; the delegated `#help-href` click copies that URL to `src` once. This is an ordinary modal iframe, without a `.dialogModal` frame ancestor. `src/Core/Header.php` uses the autoloaded `workbench-popup` bundle declared in `config/config.yaml`; its unchanged `interface/clinical-workspace/popup.js` walks same-origin parent frames to an active workbench shell and gives this nested help document `oe-workbench-context` on `<html>`, not `oe-workbench-popup`. The colors originate in `interface/clinical-workspace/popup.css`; the relevant inherited help cascade is in `interface/themes/oe-common/help-files-common.scss` and `interface/themes/colors/utilities/help-files.scss`. The route's body marker limits its context palette to this document. Standalone, legacy, and cross-origin help stay outside this context in the source-derived model.

Existing eligibility, authentication, role, ACL, and session boundaries are not cleared by preserving the caller and shared assets. The help document's own PHP bootstrap remains in place. Source and synthetic VM checks do not prove a real user's permission to reach the caller or the iframe.
