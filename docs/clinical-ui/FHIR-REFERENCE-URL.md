## Contract

`FhirServiceBase.setFhirApiUrl` supplies a base URL produced by `ConfigServer.getFhirUrl`, which can end in `/fhir` without a trailing slash. `FHIRSearchFieldFactory.createReferenceFieldType` and `resolveReferenceRelativeUrl` pass that base to `FhirUrlResolver.getRelativeUrl`; the resulting relative URL is passed to `ReferenceSearchValue.createFromRelativeUri`. Both `https://local.example/fhir` and `https://local.example/fhir/` must yield `Patient/opaque-id` from the corresponding patient URL, then resource `Patient` and ID `opaque-id`.

The resolver accepts only a URL beginning with the exact normalized base including its final slash. A sibling path or a base URL embedded in another URL's path, query, or fragment does not match. For accepted URLs, the suffix is passed through byte for byte; this contract adds no ID, query, or fragment normalization or validation. A bare base without the slash returns `null`; the base with its slash returns the historical empty string. The tests also cover HTTP and HTTPS bases, nested base paths, Encounter, string ID `0`, resource case, a different scheme or port, unrelated URLs, and null or false URL inputs under the existing casts. An empty base retains slash based behavior and is not presented as a new security policy.
