# OPEMR-94: Medical Dashboard help in the workbench

## Scope and rationale

This change gives the existing Medical Dashboard help page a paper and ink surface when its iframe is inside an active workbench. It changes only `Documentation/help_files/medical_dashboard_help.php`: one `@media screen` style block immediately after `Header::setupHeader()` and the title, before `</head>`, and one class on `<body>`. The selectors require both `html.oe-workbench-context` and `body.oe-medical-dashboard-help-popup`. They do not style standalone help, a legacy shell, or print. There is no new help action, layout, clinical text, or shared popup behavior.

The style uses the existing `--oe-wb-canvas`, `--oe-wb-paper`, and `--oe-wb-ink` tokens, with the shared popup palette as fallbacks. It paints the body, direct help container, headings, non-button help links, and redirect icons. The two `!important` declarations address the existing help theme's `!important` heading background and redirect color; they do not recolor semantic warning icons or buttons. Geometry and typography stay with the original page and theme. This is a narrow cascade preflight, not evidence of visual acceptance across themes.

## Source and activation path

`interface/patient_file/summary/demographics.php` is the actual caller. It obtains the active session, chooses `$pid` from session or request, can call `setpid()` for `set_pid`, and creates `OemrUI` with `page_id = core.mrd`, `show_help_icon = true`, and `help_file_name = medical_dashboard_help.php`. The page calls `Header::setupHeader(['common', 'utility'])`. Before the dashboard header is included, a `ViewEvent($pid)` is dispatched and `AclMain::aclCheckCore('patients', 'demo')` is checked; either failed condition renders an unauthorized partial and exits. The subsequent squad ACL can suppress the dashboard header. Only when `$thisauth` remains true does `dashboard_header.php` render `OemrUI::pageHeading()` through `patient/dashboard_header.html.twig`. The page later calls `oeBelowContainerDiv()` to emit the help modal. This source path is a precondition to seeing the icon, not a claim that the help route itself enforces those patient permissions.

`OemrUI` adds the help action only when `enable_help !== 0` and `show_help_icon` is true. Its title distinguishes `enable_help == "1"` (view Help) from `== "2"` (enable the Help Modal in user settings). The heading action has `id=help-href`, `data-target=#myModal`, and `data-toggle=modal`. `oeBelowContainerDiv()` emits an ordinary Bootstrap `.modal.fade` with an iframe `id=targetiframe`, initially empty `src`, and `data-src` pointing at `/Documentation/help_files/medical_dashboard_help.php`. The delegated click handler copies `data-src` into `src` once on first open. The modal is `.modal`, **not** `.dialogModal`.

`Header::setupHeader()` autoloads configured assets through `setupAssets(..., true)`; `config/config.yaml` autoloads `workbench-popup` (`popup.js` and `popup.css`). The unchanged controller walks same-origin parent/opener windows toward the active workbench shell and observes its `workbench-active` class. For the help iframe, that path passes through the content frame to the shell. Because neither the help iframe nor its parent frame is inside `.dialogModal`, it receives `oe-workbench-context` only, not `oe-workbench-popup`. It removes its owned context class when workbench mode turns off or on `pagehide`. Standalone, legacy, cross-origin, inaccessible, or disconnected paths cannot establish this context. The page's `@media screen` rules activate only with that context class; shared modal chrome remains governed by shared CSS.

The caller also contains patient and appointment widgets, portal and eRx paths, clinical and patient reminder fragments, allergy and medication requests, card and section render events, and a post-page-load render event. They are background caller context, not part of this styling change. The help body's three sections (`Header`, `Nav Bar`, `Data Section`), eight illustrative buttons, eight external links, and existing `#show_hide` toggle script remain byte preserved. Its portal, eRx, deceased, CCR/CCD, and Clinical Decision Rule text is historical guidance preserved as content, not newly endorsed medical or operational advice.
