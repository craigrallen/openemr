# Appointment conflict input prerequisites (OPEMR-100)

`AppointmentService::validate()` now requires a numeric `pc_duration` greater than or equal to zero and a string `pc_startTime` in exact 24-hour `HH:MM` form (`00:00` through `23:59`). Its numeric rule followed by a callback using `is_numeric($value) && $value >= 0` retains zero, numeric strings, fractions, and exponent notation without imposing an integer or upper-duration policy. Its string rule stops validation before the regex for non-string clocks. Existing required and optional fields, patient/provider lookup callbacks, and date validation remain in place.

`AppointmentRestController::post()` adds `pid`, validates, then calls `insert()` on success. The optional `pid` callback normally queries the database. `FhirAppointmentService::insertOpenEMRRecord()` defaults missing or nonpositive duration before validation. Direct `AppointmentService::insert()` calls bypass validation. These input checks are neither overlap detection nor atomic booking or conflict resolution, and do not complete feature 14. Acceptance of fractional and exponent durations by validation does not establish that persistence handles them correctly.
