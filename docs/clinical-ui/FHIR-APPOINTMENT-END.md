# OPEMR-198: FHIR Appointment occurrence end

## Native path and change

`FhirAppointmentRestController::getOne()` and `getAll()` call `FhirAppointmentService` through `FhirServiceBase::getOne()` / `getAll()`. The service searches with `AppointmentService::search()`, then maps each record with `FhirAppointmentService::parseOpenEMRRecord()`. For creation, `FhirGenericRestController::post()` routes through `FhirServiceBase::insert()`, `FhirAppointmentService::parseFhirResource()` and `insertOpenEMRRecord()`, then `AppointmentService::insert()`. That writer stores `pc_eventDate`, `pc_startTime`, `pc_duration`, and the calculated `pc_endTime`; its end clock alone cannot identify an overnight occurrence's end date. `pc_endDate` can describe a recurrence series and is not the end of an occurrence when `pc_eventDate` exists.

The read mapper now uses a finite, nonnegative, whole-second numeric `pc_duration` and an existing start time to calculate the occurrence's end calendar date. It accepts that date only when the calculated clock matches the stored `pc_endTime`. It always emits the stored end clock through the existing `UtilsService::getLocalDateAsUTC()` path. A same-day clock with an inconsistent duration therefore retains the occurrence date. Missing or unusable duration, missing start time, missing occurrence date, and missing end time retain their legacy branches. Duration is capped at 100 years of seconds for safe date arithmetic; out-of-range values retain the legacy end date. The calculation uses UTC only to select a calendar date, without changing the existing date utility's timezone or offset behavior.

## Evidence and limits

The controller saved RED evidence before the source change in `verification/appointment-read-20261031/controller-red.log`: 16 fixture cases, with eight semantic end-day failures. The standalone fixture `tests/clinical-ui/fhir-appointment-end-contract.php.fixture` now has 24 cases exercising the complete native `parseOpenEMRRecord()` method, native FHIR R4 models, and native date utility. The eight follow-up cases resolve the review's P3 coverage weakness: a duration and end-clock mismatch that would otherwise change the date, fractional and non-finite durations, an oversized numeric string, the exact 3155760000-second safety cap and the next second, and missing start time. The missing-start case characterizes the existing parser's midnight start when `pc_eventDate` is present; it defines no new missing-field policy. The cap is an arbitrary implementation safety policy, not a native schema limit. The other cases cover same-day, overnight, midnight, month/year rollover, over-24-hour, numeric-string, recurrence, fallback, and fixed-offset behavior. The JavaScript adapter `tests/js/fhir-appointment-end.test.js` invokes that PHP fixture but was not run in this phase. The fixture has a synthetic service parent, bypasses the constructor, and skips I/O branches. It covers UTC and a fixed offset only. The current date helper's DST behavior was not fixed or validated. This is not authenticated REST, persistence, security, or clinical acceptance evidence. This is supporting work for original requirement 15 (easier appointment moves), not acceptance of that requirement or the full 22-feature programme.
