# OPEMR-128: employer save with no prior history

The demographics save path calls `updateEmployerData($pid, ..., false, $patientData)` in `interface/patient_file/summary/demographics_save.php`, through the wrapper in `library/patient.inc.php`, into `EmployerService::updateEmployerData()`. The demographics page reads the latest employer through that same wrapper and `getMostRecentEmployerData()`. When there is no employer row, the native read returns `false`. Iterating it discarded the prepared submitted fields and skipped the insert. The service now merges old fields only when the read returns an array, retaining the prepared new fields for `false`. Source inspection confirms that an array result, including an empty array, keeps its prior behavior; empty-array preservation has no dedicated test. The existing server-set patient and creator IDs, patient occupation and industry, date replacement, fresh UUID, metadata-based column filtering, and insert path remain in place.

It uses the native employer and base service methods with synthetic session and UUID values; only the QueryUtils database boundary is recorded. No database, authenticated session, or live endpoint is exercised.
