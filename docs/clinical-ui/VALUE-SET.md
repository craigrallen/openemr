# ValueSet identity contract

OPEMR-241 tests the native FHIR ValueSet service's `_id` search definition. For list backed ValueSets, the expected definition is one token mapped to `ServiceField('option_id', ServiceField::TYPE_STRING)`. The `list_options` schema has `option_id` and no `id` column. `ListService::searchLists()` projects `lo.*` and joins the list name through `lo.option_id`.

The CLI fixture loads the complete native `FhirValueSetService` class, its native traits and interfaces, and the native search definition classes through a bounded autoloader. It uses a declaration-only synthetic `FhirServiceBase` parent and bypasses the service constructor. Reflection invokes the protected `loadSearchParameters()` method. The fixture checks the `_id` type, mapped field and options, and preserves the list and appointment `_lastUpdated` definitions. It separately checks that the source is either the pinned original or differs by exactly one permitted mapping replacement. The pinned original SHA-256 is `5e15b94f852cdb72759be5847cc61fc0ff0951094ab74de1bb2c597a80cc861e`.

The fixture executes the real native token resolver and WHERE builder for `custom-list`, `0`, `01`, and `appointment-type`, checking the generated column identifier and exact string bindings. The fields are manually passed from the actual reflected definition to native token objects; the parent search-parameter conversion path is not exercised. Native CodeTypesService runs with an explicitly empty installed-code map. SQL fragments are generated, never executed. The fixture does not call `getAll()`, run the appointment category shortcut, or bootstrap the application. The Jest adapter is hosted-only and calls PHP directly.

Controller prepublication test-only corrections added the CLI guard, two missing native autoload entries and the empty code map after an initial harness failure, then captured genuine original-source RED: 10 cases, 5 pass, 5 semantic failures with empty stderr. The initial four missing-CodeTypesService cases are not semantic RED. The adapter was strengthened to require all 10 exact case names/count. These nonproduction exceptions require the same complete independent review as the CLI proposal; production remains tests-first.

This supports patient-record and calendar terminology interoperability, not completion of any original feature, the researched UI, all 22 requirements or Swedish readiness. Native authenticated HTTP/SQL, roles/security, persistence and clinical QA remain unverified. No local Jest/emulation/PHPUnit/PHPStan or application bootstrap is authorized. No review bypass, merge or deployment is implied.
