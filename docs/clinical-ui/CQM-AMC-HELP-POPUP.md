# CQM/AMC help popup presentation

This slice changes only `Documentation/help_files/cqm_amc_help.php`. The existing route gets one inline screen style before `</head>` and one body class, `oe-cqm-amc-help-popup`. The two selectors require `html.oe-workbench-context`; they set the body canvas and ink and the direct `.oe-help-container` paper and ink, using the existing workbench tokens with fixed fallbacks. The body class exists in the DOM in all media, while the added CSS applies only to screen media. The original 6,440 bytes are preserved outside those two additions. Fonts, geometry, headings, translated clinical text, alert semantics, controls, links, report behavior, and shared sources are unchanged.

## Route and context

In `interface/reports/cqm.php`, `$show_help` starts false. The AMC branch selected by `CertificationReportTypes::isAMCReportType($type_report)` sets it true and selects `cqm_amc_help.php`; the other report branches do not select this help file. `templates/reports/cqm/cqm.html.twig` calls `oemHelpIcon()` when `show_help` is true and also calls `oemrUiBelowContainerDiv(oemrUiSettings)`.

Twig's `oemHelpIcon()` loads `library/display_help_icon_inc.php`. There, `enable_help` value 1 gives an active looking help icon, value 2 gives a disabled help hint and color, and value 0 gives an empty icon. Value 2 still produces an anchor with the modal target, so its disabled hint alone does not prove that the modal cannot open. `OemrUI` separately adds its help icon listener when `enable_help !== 0` and `display_help_icon` is true, and `oeBelowContainerDiv()` emits `helpFileModal()` when `display_help_icon` is true. These paths have different gates; the presentation edit does not reconcile or alter them.

`helpFileModal()` creates ordinary `#myModal` (`class="modal fade"`), with `#targetiframe` initially holding its help route in `data-src`. The existing `#help-href` click handler copies that route into `src` only on the first open. This modal lacks `dialogModal`. In an active same-origin workbench frame chain, `interface/clinical-workspace/popup.js` therefore assigns the help document `oe-workbench-context`, not `oe-workbench-popup`; the new selectors follow that context. The page's existing named heading anchor has explicit theme gray link styling, unchanged by this edit. Setting body and sheet ink does not establish contrast for that anchor or other descendants. Both `alert alert-info` blocks keep their palette and semantics, but the new surrounding background may affect perceived or measured contrast.
