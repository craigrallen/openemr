# Organization insurance insert routing

The native insurance producer in `src/Services/FHIR/Organization/FhirOrganizationInsuranceService.php` emits Organization type code `ins`. The aggregate insert method previously compared codes only with its legacy `Ins` constant, so an Organization carrying the native lowercase code fell through to the facility insert service.

The change adds the exact lowercase `ins` alternative to each existing insert condition: the legacy array branch and the native model object branch. The `Ins` constant and loose comparisons remain unchanged. Other codes, including `prov`, `pay`, and `INS`, continue to fall through to the facility service. A later matching coding or type still selects insurance. Routing still compares code without checking coding system; `ins` with a different system also selects insurance. This is an unchanged policy limit, not coding-system validation.

The CLI fixture loads the repository's actual aggregate, traits, interfaces, ProcessingResult, and FHIR model files through a case-preserving `OpenEMR` source autoloader. It constructs native FHIROrganization types and codings for the object branch. Its legacy array subclass is an explicitly synthetic boundary. A declaration-only PSR logger interface and trait support loading; logging is not used. Reflection bypasses the aggregate constructor and injects recording insert objects into its untyped child service properties. Those record the unchanged resource reference and return distinct real ProcessingResult objects. The fixture does not instantiate the actual child services or execute their SQL or other backend behavior.

Source preservation accepts the supplied original SHA256 `836dc5000110a4f86b5d56932ff19d8cb4fecd941922e0a0f7a0219c3a052943` on the baseline. On a corrected source it requires both new conditions exactly once, reverses exactly those two fragments, and compares the resulting full file to that original digest. It also checks the real insurance producer's lowercase code in source without executing the producer. The fixture reports a fixed 21 named checks in one JSON line and fails for any check failure or PHP diagnostic.

The controller captures RED before applying the product change. The fixture command is `php tests/clinical-ui/organization-insurance-routing.php.fixture`. The hosted Jest adapter is `tests/js/organization-insurance-routing.test.js`; it invokes that command through `spawnSync` and validates the status, stderr, exact one-line JSON shape, and counts. No local Jest or emulation result is asserted here.

This supports the Organization record interoperability routing case. It does not establish native authenticated FHIR POST behavior, persistence, security, roles, clinical QA, coding-system policy, the full 22 cases, UI or demo behavior, or Swedish-specific behavior. Ordinary approval and hosted CI and coverage remain separate.
