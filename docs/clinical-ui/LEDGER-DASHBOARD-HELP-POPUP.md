# OPEMR-95: patient ledger dashboard help popup

## Scope and rationale

`Documentation/help_files/ledger_dashboard_help.php` has one local presentation seam for the patient ledger help shown inside the workbench. The body class `oe-ledger-dashboard-help-popup` and a single `@media screen` style block before `</head>` pair each background with its ink: the body uses `--oe-wb-canvas` / `--oe-wb-ink` (`#f3f7f5` / `#17343b` fallbacks), and its direct `.oe-help-container` uses `--oe-wb-paper` / `--oe-wb-ink` (`#fff` / `#17343b` fallbacks). These values match the shared workbench tokens in `interface/clinical-workspace/popup.css`. The rules apply only when `popup.js` marks the help document's `<html>` with `oe-workbench-context`. They add no geometry, typography, heading, link, control, handler, or financial rule; there is no `!important`. Screen-only scope leaves print styling to the existing styles.

The original 4,100-byte help source is pinned by `tests/js/fixtures/ledger-dashboard-help-popup-original.php.txt` at SHA-256 `ea712d807796efca4bd7c54a150430944fdba4d97b98d2677229c1d69fb66acc`. The contract in `tests/js/contracts/ledger-dashboard-help-popup.cjs` specifies exactly two additions: the style block before `    </head>` and the class on `    <body>`. Removing the exact block and changing that opening body tag back to `    <body>` must restore every original byte. The 24 translated financial guidance paragraphs, named `entire_doc` h2 anchor, and illustrative `type="button"` Submit remain as written. Their historical billing instructions are preserved as source content, not endorsed as current clinical or financial guidance.

## Caller and frame preflight from source

`interface/reports/pat_ledger.php` is a 913-line financial report. Source inspection shows an active session from `SessionWrapperFactory`, a POST CSRF check when POST is nonempty, and the `acct` / `rep` ACL gate. The route reads `$_GET['form']`: `form=0` configures `show_help_icon` false with an empty `help_file_name`; the patient mode configures the icon true and `ledger_dashboard_help.php`. The `form_csvexport` branch sends CSV download headers before the ordinary HTML page. In the patient HTML branch the report includes `interface/patient_file/summary/dashboard_header.php`, which renders the OemrUI page heading; the report constructs `OemrUI` and later calls `oeBelowContainerDiv()`.

`src/OeUI/OemrUI.php` also checks the `enable_help` setting. Its help action targets `#myModal` with Bootstrap modal attributes. The modal holds `#targetiframe` with an empty `src` and the help route in `data-src`; its delegated help click assigns `src` on first open. This is the ordinary Bootstrap help modal, including OemrUI's own modal dimensions and resize behavior. The report, access controls, CSV path, modal, and lazy load code are unchanged by OPEMR-95.

The real shared controller in `interface/clinical-workspace/popup.js` walks same-origin parent windows to an active workbench shell. For this ordinary `targetiframe` it adds `oe-workbench-context` to the help document's `<html>` and does not add `oe-workbench-popup`, which is reserved for popup-class integration. It removes its owned context class on inactive mode or page hide. The new rules use only that context class and the help route's own body class, so a standalone or legacy help page retains its existing presentation.
