# OPEMR-257 clinical note status test proposal

Status: pending controller materialization and execution. This is a tests-only handoff bound to repository HEAD `09b29da7771aea334ed5745e058751157af980d7`; the binding is supplied by the controller and has not been independently attested here. No test result is claimed.

The proposed product change is a single guard replacement inside the complete native `FhirClinicalNotesService::parseOpenEMRRecord`: replace `if (!empty($dataRecord['activity'])) {` with `if (isset($dataRecord['activity'])) {`. Native `ClinicalNotesService` writes activity `0` for inactive notes, and both SELECT projections support stored integer `0` and string `"0"`. The current guard skips these values and emits `current`. The proposed guard maps them to `entered-in-error`, retains `current` for `1` and `"1"`, retains the fallback `current` for missing or null activity, and retains `entered-in-error` for nonzero `2` and `-1`. It also changes unsupported malformed `false` and empty-string values to `entered-in-error`; no preservation claim is made for every malformed value.

The CLI fixture calls the complete native mapper method and loads native FHIR models, traits, interfaces, constants, and `UtilsService` through a source-only autoloader. Its synthetic boundaries are `FhirServiceBase`, `FhirOrganizationService`, and `ClinicalNotesService` activity constants. It bypasses the mapper constructor and overrides only metadata and author population to avoid unrelated configuration and database access. Its row, organization reference, identifiers, text, date, and UTC timezone are synthetic. It does not load application bootstrap, vendor code, SQL, or a public request.

The fixture checks native getter and JSON status, fallback and nonzero cases, record order, native source provenance, unchanged nonstatus serialization, and unchanged input. Its complete-source inverse requires exactly one new guard, reverses only that guard, and compares the result with the supplied original SHA-256 `936682d607790d3a4b7ad6e96c7f0aaffa5d97e15c009ffefead07ee116190c9`. The unmodified original is expected to fail the real zero-value semantic cases and the inverse case separately. The Jest adapter requires the exact case set, strict one-line JSON output, empty stderr, and successful PHP exit.
