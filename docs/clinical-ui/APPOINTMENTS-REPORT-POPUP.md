# Appointments report filter sheet (OPEMR-25)

## Scope and rationale

The Appointments report has two existing entry paths: the ordinary report and the patient-specific popup. Both use `interface/reports/appointments_report.php`; the popup is opened by the standard menu with the patient query parameter. When `oe-workbench-context` is present on the document's `html` element, it activates this small screen-only treatment. Outside that context, the report keeps its inherited presentation. Actual context activation in each mode still needs runtime verification. The route gains only the grouped `ClinicalWorkspaceAssets` import, a web-root-escaped and versioned stylesheet link after `Header::setupHeader()`, and a class on the existing `#report_parameters` element. The link uses `media="screen"`; the stylesheet also has a single `@media screen` block. `src/Common/Assets/ClinicalWorkspaceAssets.php` gains one sorted supported basename so its fixed-list `version()` lookup can provide the per-file cache token.

The four rules in `interface/clinical-workspace/appointments-report-popup.css` are limited to `html.oe-workbench-context #report_parameters.oe-appointments-report-sheet`: an ink/paper pair for the filter sheet, an ink override for descendant `.text`, and separate `:focus` and `:focus-visible` outlines for `.form-control`, checkboxes, and button links. The descendant `.text` color is the sole `!important` declaration, needed to answer the actual Manila theme's important text color. The paired sheet colors use workbench tokens with literal fallbacks. The outlines provide a visible focus indicator without changing control geometry.

The stylesheet does not target `#report_results`, the wide results table, native control or button palette, or print output. It does not change fonts, gutters, padding, borders, wrappers, JavaScript, backend logic, or caller behavior. Theme-aware inherited fields and buttons remain as they are; native contrast has not been proved. The inherited 650px filter cell and wide results table are unresolved narrow-layout geometry. In the generic popup launcher, `500` is the initial **height**, `modal-mlg` determines width, and auto height remains subject to the viewport; this change does not solve initial or resized modal clipping.

## Preservation and verification state

`tests/js/appointments-report-popup.test.js` captures the original 689-line route and 87-line helper, constructs the exact forward edits, and reverses them to check every original byte. It also parses the CSS and rejects extra selectors, declarations, media, or changes to focus grouping. Its synthetic contracts and negative cases passed during tests-first RED. The controller confirmed the genuine hosted RED for tests-only commit `fb15f4d263897e73aac5d041360da99d539f6c95` (JS Unit Test `39031018007`): exactly the three intended actual route, helper, and CSS assertions failed; 1,265 tests passed across 62 suites. Production was unchanged at that RED checkpoint. Hosted GREEN and full CI for the production diff are still pending and belong to the controller. Source preservation is **not** security clearance and does not prove native behavior, runtime behavior, accessibility, or design fidelity.

The unchanged report still checks POST CSRF and the `patients/appt` ACL. It resets `pidList` and `apptdateList` on each load, including GET, and performs session writes later in the route. The original form POST, search/filter criteria, sorting, reminders, CSV download, printing, address labels, fee sheets, and other actions remain in place. This is source-level preservation only; real submit, sort, export, print, and opener behavior await runtime checks.
