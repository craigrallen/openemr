# ServiceRequest inbound code system regression

OPEMR-225 adds a dependency-free native CLI regression for `FhirServiceRequestService::parseFhirResource`. The PHP fixture constructs the complete native `FHIRServiceRequest` from inbound payload arrays, invokes the complete native parser, and uses native `FhirPayloadReader`, `CodeTypesService`, interfaces, and traits from tracked `src/` paths. A declaration-only framework parent and constructor bypass avoid unrelated search, procedure, UUID, and database initialization. No parser method is copied into the fixture.

Run the fixture with `php tests/clinical-ui/service-request-native.php.fixture`. Its 23rd case pins the entire original service source by SHA-256. It accepts either that exact original, solely to establish the semantic RED result, or one unique approved multiline replacement of the `procedure_code` operand whose inverse reproduces the original hash. The fixture emits one JSON report line and exits nonzero if any case fails. The Jest adapter is for hosted execution only; do not run Jest or Node locally.

The cases cover LOINC, SNOMED CT, CPT, an ICD-10-CM alias, duplicate suffixes across systems, leading zeros, exact string `0`, coding order, display and concept-text fallbacks, preserved titles, missing/unknown/malformed systems, malformed and empty codes, no-coding/text-only validation, and existing status, intent, category, priority, instruction, note, and resource-type guards. The native code helper's current `empty()` behavior would turn a known-system string `0` into an empty code; the proposed operand keeps that exact literal bare.

This is a parser mapping regression, not a persistence or clinical workflow test. Arbitrary system URLs remain bare codes. Existing prefix selection and `procedure_code` column length semantics remain in force. Subject, requester, encounter, authored date, and reason inputs are intentionally omitted because their paths need UUID, database, or date helpers outside this isolated regression. SQL, authorization and security, persistence, and clinical workflow gates require separate verification. This test does not establish a clinical outage or data-loss claim.
