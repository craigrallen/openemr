# QDM laboratory result precision (OPEMR-138)

## Rationale and scope

`LaboratoryTestService::makeQdmModel()` originally cast every nonempty, non-`Negative` result to `int` before constructing a QDM `Quantity`. That truncated fractional laboratory results, including `1.75` to `1`, `0.25` to `0`, and `-2.75` to `-2`. The value conversion now uses native numeric arithmetic for numeric results: integer values and integer-form strings remain exact integers, while finite, in-range fractional values remain floats. Nonnumeric, nonfinite, and out-of-range values retain the original `(int)` fallback and its applicable PHP diagnostics. For example, `1.5 mg` still becomes `1` and lowercase `negative` still becomes `0`. Numeric overflow strings retain their original integer-cast results. The conversion does not promise the decimal precision of arbitrary real numbers beyond PHP's native numeric types.

The change is confined to conversion immediately before the `Quantity` value assignment. The existing empty and zero guard still leaves missing, `null`, `false`, empty string, integer `0`, and string `'0'` as the existing `'Negative'` result. Exact string `Negative` still takes the existing SNOMED CT code path. Units still come from `record['units']`; dates, period bounds, procedure codes, input record data, SQL, and the wider QDM quantity policy are unchanged. This supports preservation of fractional laboratory values without losing the type and precision of native integers in the QDM mapping; it does not complete original22, a researched UI, or Swedish readiness.
