# OPEMR-255: SOAP text retention test scope

Status: implemented and locally exercised by the controller; independent static review and hosted acceptance are separate gates. The controller owns materialization, Git operations, and execution. The original baseline was `09b29da7771aea334ed5745e058751157af980d7`; it is not the candidate HEAD. Exact candidate HEAD and frozen artifact hashes are recorded in the controller evidence under `verification/soap-text-retention-20261116/frozen-review.json`. Inline authors and reviewers do not independently attest repository HEAD, hashes, or runtime.

The native save path uses `C_FormSOAP`. Its `default_action_process` calls parent `populate_object` before persistence, and `Controller::populate_object` calls the SOAP setters for posted fields. On a loaded note, the original four setter guards ignored empty string and string zero, leaving old text in those properties. The fixture directly exercises the complete native `FormSOAP` class through its four setters, getters, and public properties. It creates a declaration-only `ORDataObject` in the real namespace and bypasses the native constructor with reflection. Synthetic input values are used throughout.

The fixture reports 38 independent named cases as one JSON line. It checks empty string clearing, string zero retention, normal text, Unicode, newline and whitespace byte retention, repeated overwrite, unchanged other fields, and unchanged input values. It also checks the historical behavior for null, false, integer zero, float zero, empty array, and truthy number, bool, array, and object inputs. Object assignment is checked by identity. A separate source check requires exactly one complete corrected fragment per setter and exactly four corrected guards, reverses those four additions, then compares SHA256 with the supplied original `e7afff2cd8d2b63c29c172e4168f6f83abcd06cef4d82ae679e9b128dfa6d48a`. The source check supplements the semantic cases; it does not replace them.

Before product edits, the controller executed the tests-only candidate `7e1a6ae9` against the unchanged original source: 25 cases passed and 13 failed (12 semantic empty, zero, and overwrite failures plus the expected source-inverse failure), exit 1 with empty stderr. After the four guard changes, all 38 cases passed, exit 0 with empty stderr. These are actual controller execution results, not independent reviewer runtime evidence or authenticated persistence acceptance. The product change is limited to `set_subjective`, `set_objective`, `set_assessment`, and `set_plan`: in each, only `if (!empty($data)) {` becomes `if (!empty($data) || is_string($data)) {`. Every other product byte and historical nonstring behavior remains unchanged under the tested inverse. Existing invalid nonstring behavior is deliberately retained; these tests do not claim input safety or validation.

The fixture does not invoke persistence, the controller, HTTP, the database, locks, ESign, roles, or security checks. Authenticated native save and readback, persistence, lock and ESign behavior, roles and security, and clinical acceptance remain distinct QA work under ordinary approval. Allocation is one implementation pass, with at most two including that QA. The scope is original2 native editor text retention only. Editable heading selection from PR135/OPEMR61 needs actual mapping, storage, and review and is not promoted here. This does not claim full22, Swedish completion, or UI coverage. No merge, deploy, master, database, patient, national, vendor, cron, audit reviewer, Swedish clone publication or installation, root checkpoint write, or historical denied retry is part of this work.
