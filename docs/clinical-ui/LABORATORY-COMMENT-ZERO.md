# OPEMR-246: laboratory comment `"0"`

The native laboratory Observation parser retains the meaningful string `"0"` as `Observation.note[0].text`. Its minimal predicate is `(!empty($dataRecord['comments']) || ($dataRecord['comments'] ?? null) === '0')`, preserving the previous handling of every other value and every other production byte.

Controller original-source RED: 13 cases, 9 passing and 4 zero-comment semantic failures before the product edit. An initial fixture incorrectly expected native annotation objects; the mapper's native `addNote` actually retains its supplied arrays. The controller corrected that test-only shape and added a CLI-only guard before recapturing genuine RED; the initial output is retained separately.

The PHP CLI fixture registers the repository's `OpenEMR\` source autoloader, loads the native laboratory service, its traits, and native FHIR model classes, then calls the native parser and serializes the returned model. It uses a declaration-only base class and bypasses the service constructor to avoid database initialization. The synthetic row has a fixed report timestamp and a noncoded `normal` result. Tests cover the native getter and JSON, Unicode, omission cases, whitespace, nonzero strings, integer zero, multiple specimen note order, and complete serialized observation equality except for the added zero note. The source-preservation case accepts the supplied original SHA256 or exactly one approved predicate replacement whose reversal restores that SHA256; it does not normalize the source.

The controller should first run the fixture against the original source and retain its semantic RED result for the string-zero cases. After applying only the approved predicate, run `php tests/clinical-ui/laboratory-comment-zero.php.fixture` and the hosted Jest adapter `tests/js/laboratory-comment-zero.test.js`. The fixture emits one JSON report line and exits successfully only when all cases pass. No execution result is claimed here.

This is supporting interoperability evidence, not completion of all 22 items. Synthetic-row parsing and native model serialization do not test SQL hydration, authenticated FHIR requests, security, persistence, or clinical conformance. Malformed comments and broader production type handling are outside this change.
