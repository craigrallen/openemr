# Immunization dose read precision (OPEMR-132)

`immunizations.amount_administered` is `FLOAT DEFAULT NULL` in `sql/database.sql`; the 4.1.2-to-4.2.0 upgrade changes the column to `FLOAT`. The native `ImmunizationService` read serializer previously applied `intval`, discarding a stored fractional dose such as `0.5`. It now casts numeric values to float after the parent serializer and retains the original `intval` conversion for other values. This is a read conversion only: it changes no input validation, stored data, database write, migration, or unit.

## Contract and consumers

For numeric database values and numeric strings, the service result contains a PHP float with the fractional value retained. Whole values intentionally become floats too; ordinary JSON encoding typically emits a whole numeric token for them. The serializer adds no decimal formatting or fixed precision policy. Other values use the legacy `intval` conversion and its result becomes a float, including empty and nonnumeric strings and booleans. A present `null` dose still becomes numeric zero, and a missing dose still raises one undefined array key warning and becomes numeric zero; neither legacy case is redefined as an unknown dose. Binary UUID fields are still converted by `BaseService`; `primarySource` still uses the exact `'1'` comparison; dates and `amount_administered_unit` are unchanged. The input row is not mutated.

The native REST controller's single and list reads call `ImmunizationService::getOne` and `getAll`, respectively, then pass the processing result to `RestControllerHelper`. Its OpenAPI annotations declare `openemr_auth`. The FHIR service also reads through `ImmunizationService::getAll` and forwards the resulting dose and unit into `FHIRQuantity`, but its existing `parseOpenEMRRecord` condition only sets `doseQuantity` when `administration_site` is nonempty. This change does not remove that condition or establish FHIR endpoint behavior. No authenticated REST/FHIR endpoint or JSON runtime response was exercised here; their authorization, session, and patient access behavior requires separate verification.

## Evidence and remaining gates

The committed native isolated test seam is `tests/Tests/Isolated/Services/ImmunizationDosePrecisionTest.php` (tests-only commit `7d1c8629`). It deliberately bypasses the service constructor, which initializes database UUIDs, while calling the real child serializer, parent serializer, and UUID conversion. Synthetic rows cover fractional, whole, zero, `null`, and missing doses, unchanged units and input, primary-source comparison, all six UUIDs, and date conversion. The correction adds present empty and nonnumeric strings, a numeric prefix with a unit, and booleans to verify the actual fallback result. Each test runs in a separate child process because its `OPENEMR_STATIC_ANALYSIS` constant is irreversible within that process; the constant prevents a database query while loading `BaseService`. The controller's local external dependency loader is evidence from its RED run, not a shipped test requirement. This seam does not exercise a database, controller, JSON response, or FHIR endpoint.

Before the production edit, the controller ran the genuine native RED on PHP 8.5.12 and PHPUnit 11.5.56: 20 tests, 47 assertions, 10 failures, 0 errors. Nine failures were fractional values and one was the parent-context dose assertion. The latest pre-correction GREEN run reported 20 tests, 92 assertions, and zero issues. A broader Services run reported 844 tests, 2095 assertions, exit 0, with one warning, one skipped, and one incomplete test. Hosted PHPStan Analyze run `40122157084` then failed with `Cannot cast mixed to float.` for the direct cast. This correction narrows the numeric branch with `is_numeric` and keeps a real legacy fallback. The new tests and hosted PHPStan still need controller reruns; counts can increase. PHPStan's shared `argument.type.php` baseline contains an entry for `intval(mixed)` in this service, and the rerun must confirm whether the fallback still matches it. The baseline is unchanged. The isolated repeat command is `vendor/bin/phpunit -c phpunit-isolated.xml tests/Tests/Isolated/Services/ImmunizationDosePrecisionTest.php`.

Database `FLOAT` and PHP floats remain subject to binary floating-point rounding, so this change does not guarantee exact decimal arithmetic or resolve a broader dose precision policy. Clinical and legal review, authenticated ACL and session checks, end-to-end reads, persistence verification, and ordinary approval remain open. It establishes no full clinical UI or all-22-feature acceptance. Merge and deployment are outside this change.
