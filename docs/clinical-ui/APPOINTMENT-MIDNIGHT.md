# OPEMR-79: appointment editor midnight conversion

## Scope and call chain

This Phase 2 change applies to the existing occurrence editor at `interface/main/calendar/add_edit_event.php`. The form posts back to that same file. Its Save and Duplicate actions run `validateform()` then `SubmitForm()`; for a single provider outside the provider tab, `SubmitForm()` checks the slot through `find_available('&cktime=' + mins)`. `find_available()` in `add_edit_event.js` opens `find_appt_popup.php` with the edited date, duration, provider, facility, category and event ID. The popup can call the editor's existing `setappt(year, mon, mday, hours, minutes)` callback to put a selected occurrence into the form. Its available-slot path submits the editor form, where the Save/Duplicate branch computes `starttime` and `endtime` before the existing insert/update, recurrence and event-hook logic.

The two corrected callers are the server Save/Duplicate hour conversion through `AppointmentTime::to24Hour()` and the inline `SubmitForm()` availability minute calculation through `getAppointmentStartMinutes()` in `add_edit_event.js`. Both treat 12 AM as hour 0, retain 12 PM as hour 12, add 12 to PM hours below 12, and retain the 24-hour/no-meridiem path. The existing minute parse and duration/end-time arithmetic remain in their original paths. `setappt()` and `find_available()` are unchanged.

## Asset cache follow-up

The editor loads `add_edit_event.js` with a per-file `filemtime()` version in the URL, escaped with `attr()`. If the file is missing or its mtime cannot be read, the version is `0`. This changes the URL when the script changes so a cached legacy copy does not omit the new helper. The filesystem path and mtime calculation stay in the PHP region before markup; the URL expression contains only the version. The shared asset loader is unchanged.
