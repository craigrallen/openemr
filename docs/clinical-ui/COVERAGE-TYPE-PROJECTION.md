# Coverage type projection

`InsuranceService::search()` supplies the insurer's `ins_type_code` alongside the existing coverage row, patient UUID, and insurer UUID. The inner `insurance_companies` subquery selects the column; the outer select forwards it to the row consumed by native `FhirCoverageService::parseOpenEMRRecord()`.

The existing mapper uses that value for the FHIR Coverage `type` ActCode. Codes 1, 2, 5, 6, and 9 produce `PUBLICPOL`. Codes 3, 4, 7, 8, and 10 through 17 produce `HIP`. Missing, null, and unknown values fall back to `HIP`. The fixture exercises integer and canonical numeric string values with explicitly synthetic projected rows. It does not execute the search query or represent database results.

The fixture also checks the native schema declaration, both source projections, native mapper and dependency origins, encoded and object output, input immutability, and unchanged non-type Coverage fields. Its inverse source pin restores the two approved SQL fragments and requires the exact original `InsuranceService.php` SHA-256. The original source is expected to fail the projection checks. Passing tests require the controller to apply both replacements after observing a genuine RED result.

This is a source-level interoperability check for the supporting Coverage record, supporting the original patient-record programme. It does not establish completion of the original 22 features, researched UI, Swedish readiness, native SQL execution, authorization, security, persistence, or clinical acceptance. Real SQL transport, authenticated FHIR, ordinary approval and full exact-head hosted gates remain separate.

OPEMR-228 uses one of at most two consecutive scheduled delivery runs, counting implementation and QA. Tests and the two production projection replacements were proposed by the wrapped coding CLI. Before any production change, the controller corrected test-only missing Composer loading to a native OpenEMR autoloader, normalized native object serialization through JSON, added a CLI guard, and disambiguated an original SQL fragment that is a prefix of its replacement. The initial missing-loader failures are not product RED; the corrected original-source fixture recorded three source-projection/inverse failures and six passing native/schema cases. No local Jest or emulation was run. The declaration-only parent and constructor bypass are synthetic boundaries; the complete mapper, traits, interfaces, helpers and models are native. The fixture does not enforce an OS no-I/O sandbox and never executes the InsuranceService query. All recorded denied-action boundaries remain parked.
