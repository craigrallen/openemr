# OPEMR-258 surgery Procedure coding regression

This bounded correction targets the surgery mapper's primary `Procedure.code.coding` values. The original source emitted a native typed token such as `SNOMED-CT:123` as `coding.code` while also setting its FHIR `system`. The product change is limited to the operand of `UtilsService::createCoding`: use `$codesService->parseCode($code)['code']` there. The original `$code` must still reach native `lookup_code_description` and `getSystemForCode`.

The native writer constructs `codeKey` as `codetype . ':' . code`; selected values are joined with semicolons into `form_diagnosis`. The PHP field mapping saves that as `diagnosis`, and both SurgeryService SELECT paths expose it. The mapper places the resulting codings in `Procedure.code`, not `reasonCode`. This fixture exercises that read path without invoking the writer, persistence, or an HTTP endpoint.

The PHP fixture runs only under CLI. It loads the complete native mapper, generated FHIR model, `UtilsService`, `CodeTypesService`, and their dependencies through exact case-sensitive paths under the repository's `src/` tree. The only synthetic boundaries are an empty `FhirServiceBase`, the three status constants on `FhirProcedureService`, and `lookup_code_descriptions`. The lookup seam records every original token and returns a deterministic description. The real `CodeTypesService` constructor uses `code_types = []`; the real `parseCode`, system mapping, and `createCoding` execute. Reflection bypasses only the mapper constructor so it cannot create `SurgeryService` or initialize application services. Dates and identifiers are synthetic and deterministic.

Cases check getter and serialized values separately, ordered mixed systems, leading zeroes, a bare token, typed `0`, equal suffixes under distinct systems, original typed lookup tokens, missing/null/empty diagnosis omissions, input immutability, native class provenance, other Procedure fields, encoded mode, and source inverse binding. The source check requires exactly one corrected operand and verifies that reversing it yields the supplied original SHA256 `ef0ee5358bc2cc4d31017f192645e00fb8da483d2c234ad9a5b797cce8da16a2`; it also verifies that the unpatched source fails the inverse check. Native `parseCode` takes the second colon-separated part for typed tokens, leaves bare tokens raw, strips unknown prefixes, and truncates multicolon tokens. The tests do not claim lossless handling for malformed tokens or empty delimiters.

After the CLI-authored operand correction the complete native fixture passed all 18 cases, exit 0 with empty stderr. PHP source/fixture syntax, Node adapter syntax and diff checks passed. No local Jest, emulation, PHPUnit or PHPStan was run; real hosted adapter/static gates remain separate. The Jest adapter invokes the PHP fixture with a 15-second timeout and requires a single JSON line, empty stderr, exit zero, exact case names and report keys, and every case passing.
