# OPEMR-207: portal appointment category eligibility

The portal save branch now reads the posted category through `AppointmentService::getOneCalendarCategory()` and rejects a missing row, an inactive category, a nonpatient category, or the native `CATEGORY_CONSTANT_NO_SHOW` category before the first `$formDate` assignment. Missing or null active/type fields and a missing constant field fail closed. A null constant value remains eligible, as permitted by the native selector. The rejection uses `xlt()` and terminates the request once. The guard runs unconditionally for save actions, regardless of `form_pid`.

The controller recorded the tests-only commit `2743b9ae` as semantic RED before this source change: 17 cases, 2 passed, 15 failed. The contract also checks the inverse source against a pinned baseline: all bytes outside that save prefix must match. Its cases cover eligible integer and SQL string flags, ineligible and incomplete rows, missing posted category, `form_pid` bypass attempts, and non-save actions. The Jest adapter invokes the same contract, but local Jest is outside this source implementation check.
