# OPEMR-207: portal appointment category eligibility

The portal `save` branch checks the posted category only when the native, validated integer `$eid === 0`, before the first `$formDate` assignment and before new appointment writes. It reads the category through `AppointmentService::getOneCalendarCategory(filter_input(INPUT_POST, 'form_category'))` and rejects a missing row, an inactive category, a nonpatient category, or the native `CATEGORY_CONSTANT_NO_SHOW` category. Missing or null active/type fields and a missing constant field fail closed. A null constant value remains eligible, as permitted by the native selector. Rejection uses `xlt()` and terminates the request once. The new appointment check applies regardless of `form_pid` and does not grant an exemption for posted status `x`.

Existing appointment saves keep their prior category behavior: this eligibility guard makes no new category query for `$eid !== 0` and does not reject an existing edit because its category has since become inactive. Category enforcement on existing updates is explicitly not delivered here. The route validates the existing event ID and checks appointment ownership earlier. Its native Cancel Appointment control sets status `x`, calls `validate()`, and submits `form_action=save`; it does not call the delete branch. An existing cancellation therefore follows the existing save path. This is a path-specific correction, not a broader cancellation policy.
