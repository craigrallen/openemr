# Calendar patient picker keyboard selection

The calendar appointment editor opens `find_patient_popup.php` as its patient picker. Each result remains a seven-column table row. The Name cell now contains a native button so keyboard users can focus and choose a patient. The button uses the existing escaped display name; the billing note remains in the Name cell below it. Popup-local button styling inherits the row's text color and font, keeps its background transparent, and gives keyboard focus a two-pixel outline.

Mouse and assistive-technology clicks on the button bubble to the existing row click handler. Enter and Space on the button use the containing result row and the same `SelectPatient` path. The keydown handler prevents native duplicate activation and Space scrolling. Repeated or modified Enter/Space does not select; other keys keep their normal behavior. The row ID and its existing tilde-delimited `selpid` payload remain unchanged.

Run `node --test tests/clinical-ui/calendar-patient-picker-keyboard-contract.cjs` and `php -l interface/main/calendar/find_patient_popup.php` for local verification. The portable Node contract checks the source button and popup-local style declarations, then executes the complete main inline script after PHP substitutions in `node:vm` with synthetic jQuery, DOM, and opener doubles. It exercises registered ready handlers, modeled selection, suppression, and empty results. The Jest adapter runs that portable contract when the repository's Jest suite is available.

These source-only checks do not verify compiled theme styling, computed contrast or focus paint, native keyup activation, real click bubbling, PHP rendering or bootstrap, authenticated lookup, a database, assistive technology, browser behavior, security, or clinical acceptance. Full browser and accessibility review remains necessary. Existing null-opener behavior and tilde-delimited payload limitations remain. No UI screenshot or visual-fidelity claim is made.
