# Patient narrative XHTML fixture

OPEMR-240 targets the generated FHIR Patient narrative while preserving the structured patient name. The product delta is one guarded XHTML operand; regression artifacts are a dependency-free PHP CLI fixture and a real hosted Jest adapter. The controller owns Git and execution. The supplied repository and HEAD binding were controller context; inline author/reviewer phases do not independently verify them.

The fixture loads the complete native `FhirPatientService.php`, its three native traits and interfaces, and native FHIR Patient and HumanName models through a bounded OpenEMR source autoloader. It declares only a synthetic, empty `FhirServiceBase` parent before loading the service, disables the service constructor, and invokes the real private summary and name methods by reflection. It checks exact source paths. It does not extract or evaluate production methods. Its native `getText()` value is an array, and `getName()` contains HumanName models. It also calls `json_encode()` on the actual Patient model and checks malformed UTF-8 encoding failure.

The source gate accepts SHA-256 `8b2af56023dd84106c692a53391d1d6abb8941b25505063b26f48ea25fc8710c` for the original service. After the separately authorized product change, it accepts only a source whose single fixed XHTML operand replacement inverts to that original SHA. The intended replacement escapes string narrative text with `htmlspecialchars($narrativeText, ENT_QUOTES | ENT_SUBSTITUTE | ENT_XML1, 'UTF-8')`, retaining the legacy nonstring operand. The fixture checks literal expected XHTML, input snapshots, native structured names, serialized narrative and names, and strict PHP diagnostics. Named semantic cases for special characters, injection-shaped text, and literal entities must fail on the original source. XML parsing checks the XHTML namespace and markup-free paragraph text when DOMDocument is available; the report records when it is unavailable.

This is a private method unit boundary, not coverage of the public parser, full resource mapping, encode flag, SQL, authentication, persistence, roles, browser behavior, or clinical workflow. XML control characters remain a limitation. Malformed structured UTF-8 still causes native whole-resource JSON encoding to return false; narrative substitution does not change structured name bytes. This fixture makes no claim of an XSS exploit.

This is scheduled delivery run 1 of at most 2 consecutive runs on this surface, counting implementation AND QA. Tests, implementation and review phases within this run do not consume separate scheduled allocations. The controller materializes these tests, captures genuine semantic RED and commits tests before a separately bound product phase. Default next delivery rotates to a DIFFERENT item rather than unchanged CI polling. This supports original patient-record interoperability, not completion of all 22 features, the researched UI or Swedish readiness. Hosted results, coverage, ordinary approval and native QA remain open until concrete evidence exists.

Controller prepublication test-only corrections retain the original author proposal: add an entrypoint CLI guard before any executable setup; compare malformed UTF-8 XML text with the literal replacement character while retaining raw malformed structured names; and enforce an absolute final LF in the adapter rather than JavaScript `$`. These do not modify production or claim a local Jest run. All final artifacts require independent review.

Connected source path: `FhirPatientService::searchForOpenEMRRecordsWithConfig` delegates to `PatientService::search`, whose query selects `patient_data.*`; the public mapper calls the two private summary/name methods. This fixture exercises those actual methods but not the query or full public mapper. Stopped Practitioner/OPEMR-210 artifacts and all other historical denied actions remain excluded. No route, bootstrap, constructor, database, patient-record access, signing, national integration, vendor, merge, deploy, master or cron action is part of this fixture.
