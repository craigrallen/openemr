# OPEMR-227 Questionnaire list errors

The public `list()` route returns the response produced by `getAll()` directly. On an error, `getAll()` passes the native `ProcessingResult` and success-code argument `200` to `RestControllerHelper::handleFhirProcessingResult()` before reading data or building entries. That helper returns a Symfony HttpFoundation `Response`, while the controller requires a PSR `ResponseInterface`. The error branch converts the exact helper response with `PsrHttpFactory`. Healthy searches still build a Questionnaire Bundle and serialize it once, including an empty Bundle when the service has no errors and no data.

The bridge constructor argument order is server request, stream, uploaded file, response. This is the typed constructor in the pinned Symfony `psr-http-message-bridge` v7.4.8 source at composer.lock reference `76f1a57719a4a04c0ea18678a6c9305b5dcb9da8`; the retrieved `PsrHttpFactory.php` had SHA-256 `5d2cbcdba4334983f17d71a699dda59918b47d908f66aa1d2344f1b2a401d53b`. The controller supplies those arguments through `OpenEMR\BC\ServiceContainer::getServerRequestFactory()`, `getStreamFactory()`, `getUploadedFileFactory()`, and `getResponseFactory()`, respectively. The container resolves the four interfaces separately, so their values need not be the same object.

An independent review identified the earlier P1 return-type mismatch. The initial provisional GREEN from a synthetic helper returning a PSR response did not establish native return-type acceptance. A later fixture modeled the helper's Symfony response, but its single direct `Psr17Factory` and same-object bridge assumption missed native hosted policies. Actual hosted PHPStan Analyze 42284865292 reported `forbiddenInstantiation` for direct construction of `OpenEMR\Common\Http\Psr17Factory`; actual hosted PHP Styling job 128122943959 reported the unused `FHIRBundle` import at line 22. The subsequent container-based correction assumed the wrong constructor order. Actual hosted PHPStan Analyze 42286590213 on `7fa80b0176ae38ce67dc4387d9a7fa735b2142aa` reported three constructor argument type errors: argument 2 required `StreamFactoryInterface` but received `ResponseFactoryInterface`; argument 3 required `UploadedFileFactoryInterface` but received `StreamFactoryInterface`; argument 4 required `ResponseFactoryInterface` but received `UploadedFileFactoryInterface`. Prior model and review checks missed this ABI error. The bounded correction reorders only the four getter operands. It adds no baseline, suppression, configuration, or dependency change.

The synthetic bridge checks constructor identity and order and converts the exact synthetic Symfony helper response to a PSR sentinel. An explicit old-path `Psr17Factory` double implements all four markers so a pre-fix failure is attributable to the policy or constructor checks rather than a missing test class.
